# mini-messenger

Небольшой мессенджер для личных текстовых переписок. Регистрация по логину и
паролю, поиск по точному логину, смена пароля, доставка через WebSocket.
Каждое сообщение доступно в истории не более 24 часов после отправки.

## Запуск на Windows с Docker Desktop

1. Запустите Docker Desktop в режиме Linux containers.
2. В PowerShell в каталоге проекта выполните:

   ```powershell
   Copy-Item .env.example .env
   ```

3. Замените `POSTGRES_PASSWORD` в `.env` длинным случайным паролем.
4. Запустите:

   ```powershell
   docker compose up --build -d
   ```

5. Откройте http://localhost:8000 и зарегистрируйтесь. Для проверки двух
   пользователей откройте второй аккаунт в другом браузере или приватном окне.

Миграции Alembic применяются автоматически перед запуском приложения.
Первый запуск требует интернета для загрузки образов и Python-зависимостей.

```powershell
docker compose logs -f app
docker compose down
```

`down` останавливает контейнеры и сохраняет базу в volume. Команда
`docker compose down -v` полностью удаляет базу, пользователей и сообщения.

## Доступ друзей

По умолчанию порт доступен только на самом ноутбуке. Для локальной сети задайте
`BIND_HOST=0.0.0.0`, добавьте точный адрес приложения (например,
`http://192.168.1.25:8000`) в `ALLOWED_ORIGINS` и разрешите входящий порт в
брандмауэре Windows. Это режим для доверенной локальной сети.

Для интернета нужен HTTPS через обратный прокси или HTTPS-туннель. В `.env`
укажите внешний адрес в `ALLOWED_ORIGINS` и `COOKIE_SECURE=true`, затем
пересоздайте сервис: `docker compose up -d`. Прокси должен поддерживать WebSocket.
Не публикуйте обычный HTTP с паролями в интернете. Порт PostgreSQL наружу не открыт.
Ноутбук должен оставаться включённым и не переходить в сон.

## Стек и устройство

Python, FastAPI, Uvicorn, SQLAlchemy 2, psycopg 3, PostgreSQL 18, Alembic.
Интерфейс — статические HTML/CSS/JavaScript без отдельной сборки.
Запись сообщения выполняется HTTP-запросом, доставка уведомления — WebSocket.
Повтор запроса с тем же UUID не создаёт дубль. После переподключения и каждые
15 секунд клиент синхронизирует последние 100 сообщений. Старые сообщения
доступны кнопкой загрузки предыдущих. Enter отправляет, Shift+Enter переносит строку.
Черновики и сообщения не сохраняются в localStorage.

Один процесс приложения обслуживает все соединения и задачу очистки. Не добавляйте
несколько Uvicorn workers или реплик без общего механизма доставки событий.
Модели: `users`, `sessions`, `dialogs`, `messages`. Диалог уникален для пары пользователей.

## Пароли и доступ

Логины нечувствительны к регистру: 3–32 латинских буквы, цифры или `_`.
Пароли: 8–128 символов, хеширование Argon2. Сессия действует 7 дней,
в базе хранится только SHA-256 случайного токена, cookie — HttpOnly/SameSite=Strict.
Изменяющие запросы и WebSocket проверяют Origin по списку `ALLOWED_ORIGINS`.
API всегда проверяет участие пользователя в диалоге. Смена пароля отзывает все
старые сессии; текущему браузеру выдаётся новая. Есть ограничения частоты входа
и отправки, действующие в памяти одного процесса. Открытая регистрация включена.
Восстановления забытого пароля, вложений, групп, сквозного шифрования и уведомлений
в фоне нет. Сервер имеет доступ к тексту сообщений.

## Срок хранения

Время хранится в UTC. API не выдаёт сообщения с `expires_at <= now()`.
Очистка удаляет просроченные строки при старте и затем раз в минуту.
Открытый клиент убирает их по таймеру. При выключенном приложении очистка
не выполняется до следующего старта. Часы сервера и клиентов должны быть верными.

Это ограничение доступности истории, а не гарантия физического стирания за 24 часа:
копии могут оставаться в файлах PostgreSQL, WAL, резервных копиях и у получателя.
Автоматические резервные копии не настроены. Текст сообщений не выводится в логи
приложения. Учётные записи и диалоги хранятся до удаления базы.

## Проверки и разработка

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m pytest -q
```

По умолчанию тесты используют временную SQLite в памяти для проверки поведения.
Для интеграционной проверки задайте `TEST_DATABASE_URL` с адресом **отдельной
тестовой PostgreSQL**: тесты очищают все таблицы в этой базе.
Проверяются вход, Origin, приватность, повторная отправка, TTL, пагинация,
смена пароля и доставка по WebSocket.

Для проверки в контейнере (SQLite):

```powershell
docker compose run --rm app python -m pytest -q
```

Для запуска без Docker задайте `DATABASE_URL=postgresql+psycopg://...`,
`ALLOWED_ORIGINS`, затем выполните `alembic upgrade head` и
`uvicorn app.main:app --reload`. В обычном запуске таблицы создаёт только Alembic.
